Batch invoice upload

A redesigned upload flow for dropping several invoice files at once — modelled on how Ramp-style fintech tools and document platforms (AWS S3, PandaDoc, Whop) handle bulk file intake. Four screens: drop, review, group, confirm.

Per-file readability check runs immediately on drop (blur/resolution/corrupt-file), not after upload — flags problem files while the user still has the originals on hand to retake.cf. Whop's "needs cropping" pre-flight validation

1

Default = 1 file : 1 invoice. Matches every bulk-upload pattern seen across fintech/document tools and needs zero input for the common case — a multi-invoice drop of separate PDFs.

2

Multi-page invoices are the exception, handled by explicit user action — select 2+ files, then "Combine" — rather than guessing from filenames or running OCR to detect continuation. No pattern in the research auto-detects this reliably; asking is cheap, a wrong guess is not.

3

Selecting files shows a lightweight page-order hint (order = drop order by default, editable by drag) so multi-page invoices reconstruct in the right sequence.
